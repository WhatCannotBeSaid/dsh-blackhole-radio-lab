# 黑洞电台成像验证规格（v1，第一阶段冻结）

冻结日期：2026-10-23。状态：**仅定义，未接入渲染**。
执行阶段：第二阶段按本文件实现夹具与验收，不再改动本文件的数值，除非同步升版并记录原因。

本文件回答一个问题：**一次电台成像结果，凭什么判定为对**。
它固定单位、观察者、标准条件、夹具几何、验收项与范围边界；不规定实现方式（shader 怎么改、CPU/GPU 怎么分工，属于第二阶段的设计自由）。

## 1. 单位与坐标（强制）

### 1.1 长度单位

世界单位记作 **U**。`1 U = b_crit = 1`，即临界碰撞参数为 1。**本规格禁用裸 `R`**：项目历史文档里的 `R` 同时指过世界单位、Schwarzschild 半径和 phase-1 的旧单位，是三义符号。

| 量 | 值（U） | 定义 |
| --- | --- | --- |
| `RS`（Schwarzschild 半径） | 0.3849001795 | `2/(3√3)` |
| `M`（质量） | 0.1924500897 | `RS/2` |
| 光子球 | 0.5773502692 | `3M = 1.5 RS` |
| `DISK_INNER` | 1.1547005384 | `ISCO = 6M = 3 RS` |
| `DISK_OUTER` | 4.6188021535 | `12 RS` |
| 盘峰值温度半径 | 1.5716865 | `(49/36)·DISK_INNER` |
| `b_crit` | 1 | `3√3 M` |
| `CAMERA_HOME` | (0.856, 0.401, 8.146) | r = 8.2006617 |

盘面为 **y = 0** 平面，法线 +Y。电台角位置记 `φ`，约定 `x = r·sin φ`、`z = r·cos φ`（与 `camera-rig.js` 的 `atan2(x, z)` 一致）。

### 1.2 世界 → Shader 坐标

```
(X, Y, Z)_shader = (x, −z, y)_world / RS          （行列式 +1 的真旋转，世界 +Y 盘法线 → shader +Z）
逆变换：x = X·RS，y = Z·RS，z = −Y·RS
```

shader 内部一律用 Rs 单位：`Rs = 1`、`M = 0.5`、`b_crit = 3√3/2 = 2.5980762`、`K_MU = 4/27 = 0.148148`、`ISCO(u) = 1/3`、盘 `u ∈ [1/12, 1/3]`。
查表索引 `e² = (Rs/b)²`；世界 `b = 1` 对应 shader `e² = RS² = 4/27`。

上游表：`deflection` 512×512、`inverse_radius` 64×32，RG32F，revision `e72b3f293409893a6fa25528b29572c96fc57f57`。

### 1.3 屏幕换算（默认相机、fov 42°、1280×720）

```
pxPerRad   = (H/2) / tan(21°) = 937.8321
degPerPx   = 0.0583333
pxPerUnit@home = pxPerRad / r ≈ 114.36   （仅用于粗定位）
```

阴影角：`ψ = asin(b_crit·√(1−RS/r)/r) = 0.11932830 rad = 6.8370°`，半高占比 0.31234，720p 下 **112.44 px**。
注意：`ψ` 是几何近似；`b_crit/r` 只在 `r→∞` 成立，在 r = 8.2 处两者差约 2%。

## 2. 静止观察者模型

- 观察者静止于 `r_cam`，不自转、不轨道运动（本阶段）。相机是针孔模型，位于 `C`，`fov` 为垂直视场。
- 每个像素的局部单位方向：

```
F = −normalize(C)                    （相机朝向黑洞中心；无 roll）
R = normalize(F × Ŷ)，U = R × F      （右手基，Ŷ 为世界 +Y）
n = normalize(F + R·(u·tan(fov/2)·aspect) + U·(v·tan(fov/2)))，u,v ∈ [−1,1]
```

- 局部方向 → Schwarzschild 坐标方向（`f = 1 − RS/r`，`n_r = n·ê_r`）：

```
d = n + (√f − 1)·n_r·ê_r
```

- 守恒量（shader 单位）：`u = 1/r`、`uDot = −u/tan δ`、`e² = uDot² + u²(1−u)`、`b = 1/√e²`。
  入射线判据 `uDot > 0`；俘获判据 `e² ≥ K_MU`（等价于 `b < b_crit`）。
- 红移：接收端 `g_recv = e/√f`；发射端 `g_src = e·√(2/(2−3u₁)) − u₁·√(u₁/(2−3u₁))·(ê_z·ê_z′)`；`doppler = g_recv/g_src`。
- 亮度 `∝ g⁴·profile⁴`，色度取观测温度 `T·max(g, 1e−3)` 的黑体色；颜色流水线只做一次曝光（1.15）、一次 ACES、一次 sRGB。
- 每条视线最多两个盘面交点：近侧 `u0`、远侧 `u1`，无更高阶像。

## 5. 四类夹具

### 5.1 夹具定义

每个夹具是盘面上的一个**圆形发射体**（有限尺寸盘面电台源）：

- 中心 `(r_s, φ_s, 0)`，半径 `ρ = 0.04 U`；
- 自身线性色 `(1, 1, 1)`，亮度系数 1，便于与盘面本身区分；
- ID 为整数 1..4，出现在所有读数与标签里；
- 夹具只在验证构建里存在（URL 参数或调试开关），**不接入正式渲染**。

四类几何与**本次实测**的像位置（CPU 参考 = `validate-imaging.mjs` 导出的 formulation B，笛卡尔零测地线 RK4；非 GPU）：

| ID | 名称 | r_s (U) | φ_s (rad) | 世界坐标 (x, 0, z) | b_geom (U) | 像分支 | 实测像质心 (px) | 像尺寸 (px) | 针孔锚点 (px) | 位移 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | N_near 近侧 | 2.6 | 0.654698 | (1.583191, 0, 2.062403) | 1.8208 | branch 1 | (851.10, 376.84) | 12.7 × 0.75 | (852.89, 376.98) | 1.8 px |
| 2 | F_far 远侧 | 3.2 | 3.796291 | (−1.948543, 0, −2.538342) | 1.2449 | branch 1 | (384.01, 339.59) | 4.8 × 0.80 | (496.02, 348.99) | 112.4 px |
| 3 | A_axis 近轴 | 1.6 | 3.246291 | (−0.167231, 0, −1.591244) | 0.0655 | branch 1 / 2 | 上弧 (640, 210.8)，下弧 (640, 505.4) | 141 × 16.5 / 137 × 16.5 | 不适用（源在阴影后） | — |
| 4 | W_weak 弱场 | 4.2 | 1.604698 | (4.197600, 0, −0.142400) | 3.8406 | branch 1 | (1178.00, 361.83) | 3.0 × 0.30 | (1137.10, 362.00) | 40.9 px |

`b_geom` 是相机到源中心的直线到黑洞的距离（世界单位），只用于分类，不是光学意义的碰撞参数。
`φ_cam = 0.1046980`；ID 1 的 φ 即 `φ_cam + 0.55`，ID 2 为 `φ_cam + π + 0.55`，ID 3 为 `φ_cam + π`，ID 4 为 `φ_cam + 1.50`。

### 5.2 为什么像都是细条

默认相机只比盘面高 0.401 U，视线与盘面夹角约 2.8°，所以盘面上一块半径 0.04 U 的圆形斑，在屏幕上的径向尺寸被压到 **0.3–0.8 px**，切向尚有 3–14 px。实测：

- ID 1：12.7 × 0.75 px（切向 12.7）；
- ID 2：4.8 × 0.80；
- ID 4：3.0 × 0.30。

结论：验收只能用**质心 + 分支 + 切向范围**，不能用面积或 IoU；任何按“圆斑重叠率”写的断言都会在默认相机下失败，且失败原因是投影而非成像错误。

### 5.3 分支预期

- ID 1、2、4 只测到 branch 1。branch 2 是否存在取决于是否被俘获；**若实现中出现 branch 2，必须报告位置，不得静默丢弃**。
- ID 3 必须出现两条弧（branch 1 在上、branch 2 在下），这是强透镜的标志性结果；只有一条即为失败。
- 所有夹具都要同时给出**针孔锚点**（同一相机基、无透镜）作为对照，用来区分“投影算错”与“透镜算错”。

### 5.4 测量脚本

`docs/baseline/fixtures-probe/` 存了两个只读探针：

- `probe-fixtures-coarse.mjs`：4 px 全屏扫描，用于发现像的大致位置；
- `probe-fixtures-locus.mjs`：按分支追踪半径等值线，用于得到上表的精确质心；
- `coarse-scan.json`：4 px 扫描的原始输出。

两者都 import `tools/validate-imaging.mjs` 的独立参考，不读 GPU、不写项目文件。它们**不是**验收脚本，第二阶段应把同样的几何固化进自己的 golden 生成器。

## 6. 验收项

第二阶段对每个夹具执行下列检查；括号内为本次定义的门槛。

### 6.1 颜色

- probe 模式 22 / 23（`disc0.rgb.r` / `disc1.rgb.r`）读回的**线性**通道，与 CPU 参考的 `chroma·brightness·DISC_GAIN` 差 ≤ 1/255。
- 整像素颜色（含一次 ACES 与 sRGB）差 ≤ 2/255。
- 同一夹具在 `t=0` 与 `t=3.85` 的色差 ≤ 2/255（盘面纹理在转，黑体色不变）。

### 6.2 可见 ID

- 像质心 3×3 邻域内，命中测试必须返回该夹具 ID；
- 同一像素不得同时返回两个夹具 ID；像分支重叠时必须显式记录重叠像素数；
- 无像区域（相距质心 > 10 px）必须返回 `null`。

### 6.3 像分支

- ID 1、2、4 的 branch 1 质心与上表差 ≤ 1.5 px；
- ID 3 必须出现两条弧，各自质心与上表差 ≤ 1.5 px；
- 任何额外分支（branch 2 及以上）都要记录 `(branch, 质心, 像素数)`，不设通过/失败，但缺失记录算失败。

### 6.4 标签锚点

- 2D overlay 的锚点必须是**成像后的屏幕坐标**，不是针孔坐标；
- 与 CPU 参考的成像质心差：`r_s ≥ 3 U` 时 ≤ 1 px，`r_s < 3 U` 时 ≤ 2 px（强场像的曲率更大）；
- ID 3 的两条弧各有一个锚点，或明确只标主像（二选一，写进实现说明）。

### 6.5 点击一致性

- 在像质心 ±2 px 内点击，必须返回该 ID；
- 在边缘 ±10 px 外点击，必须返回 `null`（不得靠扩大热区通过）；
- 命中测试与标签锚点必须使用同一坐标源（否则会出现“看得到点不到”）。

### 6.6 稳定性

- `t=0` 与 `t=3.85` 两次读回的质心差 ≤ 0.5 px；
- 连续两帧读回的 log 字节一致（确定性渲染，`reducedMotion: true`）。

### 6.7 回归

- `node tools/validate-imaging.mjs` 必须仍为 **197/197**、退出码 0；
- 不得放宽 `TOL_DEFLECTION 3.0e-4`、`TOL_DEFLECTION_CRITICAL 1.0e-2`、`TOL_CROSSING_U 3.0e-3`、`TOL_CROSSING_T 0.5`。

## 7. 范围边界：盘面近似 vs 任意三维源

本阶段的成像模型只能回答“视线与 y=0 平面的交点在哪儿”。由此产生的硬边界：

1. **只能与平面求交**。任何有高度的源（包括当前电台层 ±0.026–0.076 U 的高度场）都不在模型内；把它当作盘面点会引入最多 `ρ` 量级的径向误差。
2. **最多两个交点**。更高阶像（n ≥ 3）、光子环的解析结构不建模；`geodesic.glsl.js` 的注释也明确声明了这一点。
3. **背景是无限远环境贴图**，无视差；有限距离的背景物体不做透镜。
4. **临界带用 `fwidth` 统一覆盖**，保证不闪，但不保证逐像素的分支归属；跨分支的像素不应拿来判定。
5. **合成顺序是近侧覆盖远侧**的近似，不是真正的深度排序；两条分支在同一像素重叠时，颜色是加权和，不是物理遮挡。
6. **弱场是相对说法**。`b_geom = 3.84 U`（ID 4）时针孔与成像仍差 40.9 px；`b_geom = 1.24 U`（ID 2）时差 112.4 px。只有 `b_geom ≳ 8 U` 时针孔误差才降到 1 px 量级——默认相机看不到那个范围。因此**针孔不能当 oracle**，只能用独立 CPU 测地线参考。
7. **任意三维源的可行路径**只有两条：投影到盘面（接受第 1 条的误差），或留在 sprite 层做普通投影（无透镜，即当前星团模式的做法）。

## 修订 R2（2026-10-23，第二阶段修复轮）

本节的修订都有实测依据，理由记录在 `docs/phase2-fix-report.md` §1。旧条目未删除，与新条目冲突时以本节为准。

### R2.1 分支语义：三个概念必须分开

- `crossingIndex`：沿同一光线的交点编号，1 = 第一次穿过 z=0 盘面，2 = 第二次。**这是唯一允许写进接口与断言的“像的序次”字段。**
- `tableSlot`：`traceRay` 的 analytic 查表槽位（1 / 2）。只用于诊断，验收不得断言它等于像的阶次。
- `screenRegion`：屏幕方位描述（upper / lower / right 等）。只供人读。

实测反例：`radio-far-side` 的像 `crossingIndex=1` 但 `tableSlot=2`。把槽位当阶次会得出“远侧是二阶像”的错误结论。

### R2.2 覆盖与可见 ID

- 像素足迹按轴分别读取：`fwp = vec2(fwidth(point.x), fwidth(point.y))`，世界单位/像素。
- 覆盖：`wRadial = 0.5*(|ux|*fwp.x + |uy|*fwp.y)`，`cov = clamp((R - dist)/max(wRadial,1e-6) + 0.5, 0, 1)`。
- 可见 ID：仅当 `cov >= 0.5` 且该源是当前像素最亮贡献时给出。ID 通道不含发光晕，拾取范围等于几何足迹。
- 电台累积只要求“交点存在”，不得被盘面的 `critFade` 门控。

### R2.3 范围边界（新增，实测）

1. **表分辨率下界**：`inverse_radius` 为 64×32，临界曲线附近 `Δu ≈ 0.007–0.011`，对应 `Δr ≈ 0.05–0.10` 世界单位。半径 0.04 的源在该区域不能被稳定成像，只会出现在表节点附近的像素上。小于约 0.10 U 的源、或落在临界带内的源，不在本管线的可验收范围内。
2. **弱场源未定位**：`radio-weak-field` 目前有交点但覆盖恒 0，尚未定位；在定位前，任何“四类源已全部通过”的结论不成立。
3. **探针读数必须整像素**：region 原点取整；条带只有 1 px 高时，锚点质心可能落在半像素上，颜色取样要取邻域最强响应。
4. **id 扫描必须原生分辨率**：半分辨率会把 1 px 条带读成空，测到的是探针网格而不是渲染。

### R2.4 视口与过期拾取（实测通过）

- drawing buffer = `CSS × min(devicePixelRatio, pixelRatioCap)`；DPR 1 / 1.5 / 2 均已验证。
- 锚点以 CSS 左上原点暴露；探针 region 用 buffer 左下原点。
- `pick()` 返回 `frameVersion`；相机或尺寸变化后必须等于当前值。
